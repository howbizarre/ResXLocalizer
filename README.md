# ResXLocalizer

VSCode разширение, което визуализира `.resx` ресурси за локализация като таблица: колона `Key` + по една колона за всеки locale вариант (`Strings.resx`, `Strings.bg.resx`, `Strings.de.resx`, ...).

## Употреба

1. `npm install`
2. Натисни `F5` (Run Extension) — отваря се нов Extension Development Host прозорец.
3. В него отвори работна папка, съдържаща `.resx` файлове.
4. Command Palette → **ResXLocalizer: Open Resx Table** (или десен клик върху `.resx` файл в Explorer).

## Конвенция за групиране на файлове

Файловете се групират по базово име и директория:

- `Strings.resx` — базов (neutral) файл, колона `default`
- `Strings.bg.resx` — вариант за `bg`
- `Strings.de.resx` — вариант за `de`

Ключовете се вземат от обединението на всички `<data name="...">` елементи във всички файлове от групата; липсващ/непреведен превод се маркира с червено.

Всяка група се отваря в свой собствен таб, озаглавен `ResXLocalizer: <BaseName>` — по-лесно е да следиш отделните преводи, ако не искаш няколко таблици в един прозорец. Затварянето на таб демаркира само файловете, показани в него, в списъка отляво.

## Редактиране

Първата колона (**Actions**) съдържа за всеки ред бутончета **edit** (прави преводите в реда редактируеми и сменя иконата на save; повторно натискане записва стойностите обратно в `.resx` файловете — запазва коментари/форматиране, добавя нов `<data>` запис ако ключът липсва във файла) и **delete** (изтрива ключа от всички файлове в реда, след потвърждение).

Най-отгоре има постоянен празен ред за добавяне на нов ключ (винаги видим, дори при активен филтър) — със същия edit/save бутон като останалите редове; полетата стават редактируеми чак след **edit**, а **save** отказва да запише, ако полето `Key` е празно (маркира се с червен outline). Ако въведеният ключ вече съществува в групата, се появява модален диалог за потвърждение на презаписването; при отказ нищо не се записва.

## Филтриране

Под всеки колонен етикет (освен Actions) има поле за филтриране — филтрите по различни колони се комбинират с AND и остават само редовете, чиито стойности в съответните колони съдържат въведения текст (без чувствителност към главни/малки букви).

## Development

- `npm run check-types` — TypeScript проверка без емитване
- `npm run lint` — ESLint
- `npm run package` — production build (`npm run vscode:prepublish`)
